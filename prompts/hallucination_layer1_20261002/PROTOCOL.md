## 执行顺序

1. 冻结统一回答清单：以 split / case_id / question_id / answer_condition 唯一键合并最终既有回答；记录正文、实际可见案情、问题、独立裁判参考、来源与hash。内部思考过程不计入回答正文。
2. 离线引用候选清单：抽取可能的法源标题及条款位置，按唯一回答去重计数。不做幻觉判断，不声称正则覆盖全部引文；无显式引用的法律断言仍需后续语义检查。
3. 建版本化外部证据包：优先国家法律法规数据库、全国人大/最高法等官方全文；同一法源缓存复用。每条证据保存实际URL、标题、版本、条款定位、正文快照hash、取得时间及效力时间。官网入口可访问不等于已经完成法条库接入。
4. 建题级参考清单：独立于模型回答梳理必要事实/例外/要件/允许裁量范围；同题五条件共享同一版本。DS草拟不冒充专家金标准，未经验证的清单不能支持确定性遗漏结论。
5. 冒烟验收后再全量：初始按两组各选2案、每案5题、5条件，共100条已存在的完整回答（某槽位异常则单列），另补与其余分组无关的合成边界测试。每个回答单独审计，judge输入不含回答模型名和旧分数。未接入证据的试跑只能叫候选审计，不能称20类完整结果。
6. 全量持久回执与可恢复队列：成功结果不重跑；网络未知先对账；异常单列。每条输出恰好20子类，错误事件有逐字片段或遗漏清单ID，以及证据ID。解析器严格结构化校验，不靠“无/未出现”等字符串计错。最终报告标明DS自动审计与专家复核状态。

本地预处理与候选索引可先完成；全量模型调用的两个前置条件是新服务健康就绪、外部证据和题级参考可用。不能因等待资源而偷偷切换付费接口，不能因缺法源而让DS独立判来源编造。

## 统计口径

主要分层为分组×回答条件。每个子类的回答级状态为 `error / no_error / not_applicable / uncertain`；无可用完整回答单列，不进入这四种结果。

- 主表同时给：完整回答数、已评价数、检出错误回答数、待核验数、不适用数；错误率为error / (error + no_error)，必须显示该子类可评价分母和覆盖率。
- 总体受影响回答数按至少一个已支持错误的回答去重，不将20个子类率相加。总无错误仅限适用子类均评价完成且无错误；部分类型未核验不能记为整体无幻觉。
- 附表可给检出错误回答 / 全部完整回答的比例，标为“已检出比例/下限”，不能充作证据完备的真实发生率。未完成项另给上界或待核验比例。
- 同一回答重复同一根因去重；多种真正不同错误可多标签。错误事件数与受影响回答数分列。
- 来源类另报实际出现引文、完成外部核验引文、待查引文及验证覆盖率；未显式引用不等于对所有法律错误免检。
- 案件级比例另以完成必要审计的案件为分母；若做置信区间或模型差异检验，以case_id聚类，不把每案5题当独立案件。比较模型时另给同题配对完整子集，避免缺失差异误导。
- 异常记录、自动错误、人工确认错误不得混用。拒答/过滤不是无幻觉；截断回答只做独立敏感性分析，不混入完整回答主统计。
- 外部证据包或完整案情超过模型上下文限制时，先做有依据的相关条文选择/任务拆分，记录版本并验收；不得静默截断原回答、案情或必要法源。
